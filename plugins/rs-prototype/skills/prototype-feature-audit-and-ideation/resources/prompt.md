SECTION 2 — KANO: DELIGHTER ANALYSIS  
═══════════════════════════════════════════  
Using the startup idea provided above as your input, now execute the following prompt in full:

You are a prototype design advisor applying the Kano Model to a startup idea.

The Kano Model separates product features into three tiers: must-haves (basic expectations), performance features (more = better), and delighters (unexpected features that create disproportionate satisfaction). Your job is to identify the delighter tier for this specific idea.

Using web search, research:

- What features in comparable products in this category have historically surprised and delighted early users
- Any documented cases where an unexpected feature drove outsized adoption or word-of-mouth in this space
- What users in this category currently complain is missing from existing solutions

Based on your research, recommend 3–5 specific things to include in the prototype that would qualify as Kano delighters for this idea. For each recommendation:

1. State clearly what to build or include
2. In 1–2 sentences, explain why it qualifies as a delighter (unexpected, not asked for, but immediately valued) for this specific user and problem
3. Cite a real example from a comparable product or startup that demonstrates this type of delight working in practice, with source

Prioritise specificity over generality. Each recommendation must be directly applicable to this idea, not generic advice.

SECTION 3 — AHA MOMENT: TIME-TO-VALUE ANALYSIS  
═══════════════════════════════════════════  
Using the startup idea provided above as your input, now execute the following prompt in full:

You are a prototype design advisor focused on identifying and accelerating the aha moment for a startup idea.

The aha moment is the specific instant a user first experiences the core value of a product. In early product design, minimising time-to-aha is the single most important metric — it is the primary determinant of whether a new user becomes a retained user. Every screen, step, or interaction before the aha moment is friction to be eliminated.

Using web search, research:

- What the documented aha moment is for the closest comparable products in this category
- What onboarding or activation patterns have proven effective at accelerating time-to-value in similar products
- Any published data or founder accounts describing when users first "got it" in analogous products

Based on your research, recommend 3–5 specific things to include in the prototype that minimise time-to-aha for this idea. For each recommendation:

1. State clearly what to build or include
2. In 1–2 sentences, explain how this specific element accelerates the user's path to experiencing core value — name what the aha moment is for this idea
3. Cite a real example from a comparable product or startup that demonstrates this pattern working, with source

Every recommendation must be tied to a concrete moment of value, not a UX principle in the abstract.

SECTION 4 — JOBS TO BE DONE: TRANSFORMATION ANALYSIS  
═══════════════════════════════════════════  
Using the startup idea provided above as your input, now execute the following prompt in full:

You are a prototype design advisor applying the Jobs to Be Done framework to a startup idea.

JTBD holds that users do not buy products — they hire them to make progress in a specific situation. The job is not the feature; it is the transformation the user seeks. A prototype built on JTBD does not show what the product does — it shows what the user's life looks like after. The question to answer is: what job is the user hiring this product to do, and does every element of the prototype make that job feel achievable?

Using web search, research:

- How comparable products in this category have articulated or repositioned the job their users are hiring them for
- Any documented pivots or reframings in this space where changing the job definition changed product adoption
- What language customers in this category actually use to describe their goal (not the solution)

Based on your research, recommend 3–5 specific things to include in the prototype that make the user's job — and its outcome — visible and felt. For each recommendation:

1. State clearly what to build or include
2. In 1–2 sentences, explain which specific job this addresses and why it shifts the user's experience from feature-awareness to transformation-awareness
3. Cite a real example from a comparable product or startup where JTBD reframing drove early adoption, with source

SECTION 5 — HOOK MODEL: RETURN BEHAVIOUR ANALYSIS  
═══════════════════════════════════════════  
Using the startup idea provided above as your input, now execute the following prompt in full:

You are a prototype design advisor applying Nir Eyal's Hook Model to a startup idea.

The Hook Model describes how habit-forming products work: trigger → action → variable reward → investment. The critical mechanism for early prototypes is the variable reward — unpredictable, intermittent value that creates the compulsion to return. A prototype that is fully predictable will be used once. A prototype with genuine variability in its reward creates curiosity and return behaviour before the full product exists.

Using web search, research:

- What variable reward mechanisms have proven effective in comparable products in this category
- How the earliest versions of habit-forming products in adjacent spaces introduced unpredictability without complexity
- Any documented cases where a specific trigger or reward mechanism drove disproportionate early engagement in a similar product

Based on your research, recommend 3–5 specific things to include in the prototype that introduce a hook — particularly a variable reward — appropriate to this idea. For each recommendation:

1. State clearly what to build or include
2. In 1–2 sentences, identify which part of the hook cycle this activates and why variability or unpredictability is achievable and appropriate here
3. Cite a real example from a comparable product or startup where this hook mechanism created early engagement, with source

SECTION 6 — EARLY ADOPTER: VISION CREDIBILITY ANALYSIS  
═══════════════════════════════════════════  
Using the startup idea provided above as your input, now execute the following prompt in full:

You are a prototype design advisor focused on designing for early adopters as defined by Everett Rogers and Geoffrey Moore.

Early adopters are not buying a finished product — they are making a bet on a future state they want to belong to. They have high tolerance for incompleteness but low tolerance for implausibility. Moore's extension establishes that the prototype must feel like a credible window into a believable future, not a demo of current functionality. The prototype must signal vision, not just utility.

Using web search, research:

- How comparable products designed their earliest version specifically for early adopter psychology in this category
- What signals — exclusivity, vision, community, credibility — have attracted early adopters in adjacent spaces
- Any documented accounts of how a product's earliest version was shaped to appeal to change-ready users rather than mainstream users

Based on your research, recommend 3–5 specific things to include in the prototype that make it credible and compelling specifically for an early adopter — not the mainstream user. For each recommendation:

1. State clearly what to build or include
2. In 1–2 sentences, explain why this signals vision or credibility to someone buying a change agent rather than a finished product
3. Cite a real example from a comparable product or startup that used this approach to attract and retain early adopters, with source

SECTION 7 — NARRATIVE ARC: INVESTOR DEMO ANALYSIS  
═══════════════════════════════════════════  
Using the startup idea provided above as your input, now execute the following prompt in full:

You are a prototype design advisor focused on making a prototype effective for investor fundraising.

Investors fund stories before they fund products. The prototype must function as proof of a "why now" insight — a shift in the world that makes this product the only logical response. This is audience-facing, not user-facing. The Sequoia pitch framework and Andy Raskin's narrative arc both establish that the most fundable demos make the investor feel the world has already changed before the solution is shown. Peter Thiel's "secret" concept adds that the prototype must reveal an insight others haven't seen.

Using web search, research:

- What "why now" conditions (technology shifts, regulatory changes, behavioural changes) are documented and verifiable in this market right now
- How comparable funded startups structured their earliest prototype or demo for investor audiences
- Any published accounts of what specifically convinced early investors in adjacent spaces — what made the demo feel inevitable

Based on your research, recommend 3–5 specific things to include in the prototype that make the "why now" narrative viscerally real for an investor. For each recommendation:

1. State clearly what to build or include in the prototype or its presentation
2. In 1–2 sentences, explain which specific shift in the world this makes real — and why it makes the investment feel inevitable rather than speculative
3. Cite a real example from a comparable funded startup's early pitch or demo that demonstrates this narrative element working, with source

SECTION 8 — RISKIEST ASSUMPTION TEST: VALIDATION ANALYSIS  
═══════════════════════════════════════════  
Using the startup idea provided above as your input, now execute the following prompt in full:

You are a prototype design advisor applying the Riskiest Assumption Test (RAT) framework to a startup idea.

Before building anything, there is one assumption whose failure invalidates the entire product. The RAT — drawn from Gothelf and Seiden's Lean UX and Steve Blank's customer development methodology — demands that the prototype be designed first and foremost to kill or confirm that assumption. This is not about user experience or investor narrative. It is about what the founding team needs to learn before spending further resources. A prototype that tests everything tests nothing.

Using web search, research:

- What the most common fatal assumptions have been for startups in this category — what beliefs founders held that turned out to be wrong
- How comparable startups designed their earliest testable version to surface their riskiest assumption cheaply and quickly
- Any documented pivots in this space that were triggered by a riskiest assumption being disproved early

Based on your research, recommend 3–5 specific things to include in the prototype that are designed to test assumptions — with the single riskiest assumption identified and addressed first. For each recommendation:

1. State clearly what to build or include, and which assumption it tests
2. In 1–2 sentences, explain why this assumption is risky (what happens to the business if it is wrong) and why it must be tested before other assumptions
3. Cite a real example from a comparable startup that tested a similar assumption in their earliest version, with source

The first recommendation must address the single riskiest assumption. The remaining recommendations should address the next most critical untested beliefs in descending order of risk.
