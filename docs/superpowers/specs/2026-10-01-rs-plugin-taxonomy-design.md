# RS Plugin Taxonomy Migration — Design

**Date:** 2026-10-01
**Branch:** `refactor/rs-plugin-taxonomy`
**Source:** *RS Managed Agents — Plugin Taxonomy & Setup Guide* (28 Sep 2026), setup steps 1–6.
Step 7 (release + team announcement) is **out of scope** for this branch.

## Goal

Replace the catch-all `rightshift-doc-gen` plugin (root `.claude-plugin/plugin.json`, `source: "./"`)
and the separate `chatbot-forge` / `delivery-agent` plugins with twelve job-named `rs-*` plugins,
authored under `src/plugins/` and generated into `plugins/` by `make sync`.

## Decisions

| Question | Decision | Why |
|---|---|---|
| Prompt-only taxonomy entries (~40 prompts with no `SKILL.md`) | Wrap each as a skill (`SKILL.md` + generated `resources/prompt.md`) | Guide requires twelve listed plugins and `make verify` failing on an empty plugin; it treats every table entry as a skill |
| Entries the guide marks planned / idea stage (`blog-agent`, `weekly-status-report`, `delivery-variance-tracker`, `hour-reporting-invoice-reconciliation`) | Not wrapped. The idea-stage prompt moves into `rs-project-management/prompts/` only | Guide: "Bold entries don't exist yet" |
| `src/prompts/misc/untitled-new-page.md` | Deleted | Blank Notion page, no content, no owner |
| `delivery-agent` plugin (8 skills) | Folded into `rs-delivery`; plugin name retired | Guide lists `delivery-agent` under `rs-delivery`; every plugin carries the `rs-` prefix |
| Root `qa-framework/` (`qa-test-planner` skill) | Moved into `rs-qa` as `skills/qa-test-planner/` | Folder renamed to match the frontmatter name |
| `product-thinking-course` (only on `origin/feat/product-thinking-course`) | Merge that branch into this one first; skill lands in `rs-product` | Guide places it in `rs-product` |
| Speaking-engagement (4 prompts) | One skill `speaking-engagement`; the four prompts ship as `resources/` files | Guide lists it as one entry with four parts |

## Target layout

```
.claude-plugin/marketplace.json        # catalogue; NO plugin.json at root
plugins/                               # GENERATED by `make sync` — never hand-edit, committed
  rs-<name>/.claude-plugin/plugin.json
  rs-<name>/skills/<skill>/SKILL.md (+ resources/, scripts/, …)
src/
  plugins/                             # SOURCE OF TRUTH
    rs-<name>/
      .claude-plugin/plugin.json
      skills/<skill>/SKILL.md          # authored; prompt-backed skills omit resources/prompt.md
      prompts/<NN-skill or skill>/{current,versions,improvements}/
      sync.json                        # optional: plugin-local generation rules (see below)
      tools/                           # optional: plugin-local generation scripts
  standards/document-formatting-standard.md
  tools/sync_plugins.py  verify_skills.py
  orchestrator/  _meta/  _workspace/   # unchanged locations
```

Only `.claude-plugin/`, `skills/` and `README.md` are copied into `plugins/<name>/`.
`prompts/`, `sync.json` and `tools/` stay source-only, so version history never ships.

Removed: root `.claude-plugin/plugin.json`, root `skills/`, `chatbot-forge/`, `delivery-agent/`,
`qa-framework/`, `src/01-…08-*`, `src/prompts/`, `src/supporting/`, `src/chatbot-forge/`,
`src/delivery-agent/`, `src/d2-diagrams/` (all moved under `src/plugins/`).

### New wrapper shape

Same as `brd-generator`: frontmatter `name` = folder, `description` ≤ 1024 chars stating what it
produces and the trigger phrases; body sections *When to use*, *Not for* (from the taxonomy row's
"Not for"), *How to run* ("Read `resources/prompt.md` and follow it exactly"). Prompt bodies are not
edited.

### Prompt folders

Existing numbered folders keep their names and `current/versions/improvements` contents
(`rs-scoping/prompts/01-brd-generator/`, … `rs-delivery/prompts/08-spec-generator/`).
Flat prompts become `prompts/<skill>/current/<original-file>.md`.

## Generation (`make sync`)

`src/tools/sync_plugins.py` replaces the Makefile's per-file `cp` lines and `extract_pack.py` call:

1. Guard: abort if `git diff --quiet -- plugins/` fails (uncommitted edits in generated dir), unless `FORCE=1`.
2. For each plugin in `PLUGINS`: `rm -rf plugins/<p>`, copy `.claude-plugin/`, `skills/`, `README.md`
   (excluding `node_modules/`).
3. Apply `src/plugins/<p>/sync.json` if present:
   ```json
   {
     "prompts":   { "<skill>": "prompts/<dir>/current/<file>.md" },
     "copy":      [ { "from": "<path rel. to repo root>", "to": "skills/<skill>/resources/<file>" } ],
     "post":      [ "tools/extract_pack.py" ]
   }
   ```
   `prompts` → copies to `plugins/<p>/skills/<skill>/resources/prompt.md`.
   `copy` → formatting standard, estimation template, speaking-engagement's four prompts.
   `post` → scripts run from repo root after copying (estimation Master Context Pack).

The estimation exception is preserved exactly: `prompt.md` comes from
`improvements/estimation-agent-v2.md`, the Master Context Pack from `current/…-v1.6.md` — same as today.
The formatting standard is copied into the same eight skills as today.

## Verification (`make verify`)

`verify_skills.py` walks `plugins/`:
- every name in `PLUGINS` has `plugins/<p>/.claude-plugin/plugin.json`, valid JSON, `name == <p>`, `version` == `package.json` version
- every plugin has ≥ 1 skill
- every skill: frontmatter present, `name` == folder, lowercase-hyphen ≤ 64 chars, `description` present
- every skill listed in a `sync.json` `prompts` map has `resources/prompt.md`
- skill names unique across plugins
- every `marketplace.json` RightShift entry has `source: "./plugins/<p>"` that exists, and every plugin is listed
- d2-diagrams render script present; estimation fill-script smoke test (unchanged)

Failure modes it must catch: deleted `SKILL.md`, missing manifest, empty plugin, version drift.

New plugin manifests start at `version: "2.4.0"` (current) so the release bumps every plugin together.

## Testing

- `make verify` passes on the finished branch; deleting any one `SKILL.md` makes it fail.
- `make sync` on a clean tree leaves `git status` clean (generation is deterministic and committed).
- Diff check: for the eight existing doc-gen skills and d2-diagrams, `plugins/rs-*/skills/<s>/` content
  is byte-identical to the old `skills/<s>/` apart from intended reference edits.
- All JSON manifests parse; `claude plugin validate` run on each plugin dir if available.
- `npx rightshift-skills` into a temp dir installs all skills.
